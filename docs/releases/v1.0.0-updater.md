# The updater's real run (issue 79)

`acs` replacing itself from a real GitHub Release, the check decision 0054 asks for before
`v1.0.0`. Machine: Windows 11 Home (x86_64) with Avast running, Windows PowerShell 5.1. Run by the
human on 2026-11-22.

## What was run

1. `v1.0.0-rc.2` installed with the release's PowerShell installer into a test folder, so the
   human's own `acs` was left alone:
   `ACS_CLI_INSTALL_DIR=$HOME\acs-rc-test`, `ACS_CLI_NO_MODIFY_PATH=1`,
   `ACS_HOME=$HOME\acs-rc-test\home`, then
   `irm https://github.com/acs-hq/acs/releases/download/v1.0.0-rc.2/acs-cli-installer.ps1 | iex`.
2. `acs doctor` from the test folder.
3. `v1.0.0-rc.3` tagged and published.
4. `acs update`, `acs --version`, `acs doctor` and a listing of the test folder's `bin`.

## Result

| Check | Result |
| --- | --- |
| Install method detected from the installer's receipt | `doctor`: "acs 1.0.0-rc.2, installed with the installer. Updating is on. Not checked yet." |
| Download, signature, trial start and swap | `acs update`: "Updated acs from 1.0.0-rc.2 to 1.0.0-rc.3." The archive's signature, made by the release's `Sign release` job from the secret, verified against the key compiled into `acs` |
| The new file runs | `acs --version`: `acs 1.0.0-rc.3` |
| State and `doctor` | "Newest known: 1.0.0-rc.3, checked just now. Last update: 1.0.0-rc.2 to 1.0.0-rc.3, just now." |
| Files left behind | `acs.exe` (14,308,864 bytes) and `acs.exe.old-1795387156` (the rc.2 file, 14,308,352 bytes), as designed: the old file goes at the next check |
| Antivirus | Avast did not block or quarantine the installer, the download, the trial start or the new `acs.exe` |

## What it took to get there

- **`v1.0.0-rc.1` was tagged but never published.** GitHub no longer runs the `macos-14` image
  `dist` picks for `aarch64-apple-darwin`; that build was cancelled, and a release is published
  only when every build succeeds. `dist-workspace.toml` now builds Apple Silicon on `macos-15`.
  rc.2 became the installed build and rc.3 the update.
- **Version-dependent tests.** The updater's end-to-end tests pretended to run `0.9.0`, a stable
  build, which does not follow pre-releases; at version `1.0.0-rc.1` they found no update. They
  now pretend to be `0.9.0-rc.0` when the version is a pre-release. Run the whole suite after every
  version commit.
- **CI.** `is_scoop` split paths with the platform's separator and failed on macOS and Linux; a
  macOS test flaked on git's background maintenance (`maintenance.auto` is now off in the test
  worlds). The perf job runs only on request since decision 0055.
- **A failing release check that is not the updater's:** the second `acs plugin install
  claude-code` with real Claude Code on Linux does not say "Nothing to change" (issue 84). It
  failed in the rc.2 and rc.3 runs, after the release was published.

## Not covered

- Windows on ARM, Scoop installs (notice only) and macOS and Linux (notice only, decision 0054).
