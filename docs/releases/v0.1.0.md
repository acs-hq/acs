## M1 gate with real sessions

`tests/e2e/real/three_sessions.sh`: three `claude -p` sessions start together in one work tree of a
throwaway repository. Each must add a function to `src/pricing.py`, a line to `CHANGELOG.md`, change
a file of its own and commit. A session that is blocked does the rest and stops; the next round
restarts whoever has work left. `check.mjs` judges each run from Claude Code's own logs, so it does
not rest on what ACS recorded about itself.

| | Run 1: ACS tools allowed | Run 2: ACS tools withheld |
| --- | --- | --- |
| Sessions, over rounds | 6, over 3 | 6, over 3 |
| Successful file writes | 9 | 9 |
| Added lines lost | 0 | 0 |
| Calls blocked in the logs | 1 (`acs_claim`) | 6 (`Edit`, by the hook) |
| Collisions in `acs status` | 1 | 6 |
| Tasks in `HEAD` at the end | 3 of 3 | 3 of 3 |
| Commits with an `ACS-Session` trailer | 5 of 5 | 4 of 4 |
| Reported cost | $1.09 | $0.71 |

Each run is the proof for a different thing. In run 1 the agents read `acs_status` and worked around
each other, so no `Edit` was ever blocked; that shows coordination, not the gate. Run 2 sends them
straight to `Edit`: the first to reach a file got it, the others were refused and quoted the holder,
and all three tasks landed once the holder finished. The check itself was tested: with `apply_tax`
removed from the file by hand, it fails and names the lost lines.

No blocked agent tried to get around a denial. Not covered by these runs: sessions in separate
worktrees, two machines, and a commit rejected by the git backstop, which no real session reached
(`tests/e2e/husky.rs` covers it with scripted seats).

Friction seen, none of it a gate failure:

- `acs_release` without `paths` is an error, and two sessions tried that first.
- A blocked session can commit code that imports a function not added yet. That happened three times,
  and each agent said so in its commit message.
- A blocked session can leave uncommitted work in a shared work tree. The next session picked it up
  (`src/orders.py` in run 2), but nothing guarantees that.

Sealed paths under the adversarial basics are `tests/e2e/sealed.rs`, with scripted seats. The real
denial of a sealed path is in the table above.
