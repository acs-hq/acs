# 0005: Policy loader

Date: 2026-10-29 (WP1.1)

## Context

`acs-policy` turns `.acs/policy/{config,guards,territory}.toml` into the `PolicyView` the engine queries (decision 0004). SPEC section 5 fixes the glob dialect and the file schemas, section 11 the failure mode (an invalid policy falls back to the last valid compiled one, else to the built-in default guards), and the plan sets a budget: loading a cached policy takes under 1 ms.

## Decision

**Own glob matcher, not `globset`.** The dialect is small (`*`, `?`, `**` as a segment, `[..]`, `{a,b}`, no negation), so `crate::glob` implements it directly. Measured in a release build for 66 patterns (30 zones x 2 globs plus the 6 default sealed globs): building a `globset::GlobSet` takes about 840 us, the own matcher about 65 us. `globset` alone would consume the whole 1 ms budget. The own matcher also gives the exact spec semantics: `a/**` matches `a` itself ("zero or more segments"), which `globset` does not, and which matters for a worktree's `.git` file. `globset` stays as a dev-dependency: a test compares both matchers on 15 patterns x 29 paths. Matching is iterative (backtracking only to the last `**` or `*`), so hostile paths cannot cause exponential time.

**Dialect details beyond the spec text.** No escape character: a literal special character goes in a set (`[*]`, `[{]`). A backslash anywhere is an error, because it is almost always a Windows separator and would silently mean something else. Rejected with a message and a fix: empty pattern or segment (`a//b`, trailing `/`), leading `/`, `.` and `..` segments (they never match a normalized path; this catches `./src/**`), `**` inside a segment (`a**b`), negated sets, `/` inside a set, reversed ranges, unbalanced braces, and more than 64 `{}` expansions. `{}` groups nest and may contain `/`. A pattern without wildcards matches only that exact path; use `dir/**` for a directory's contents (and the directory itself). Case-insensitive mode lowercases pattern and path character by character.

**Zone specificity.** All matching zone globs compete (each `{a,b}` alternative separately); the winner has, in order: (1) more leading literal segments, (2) fewer `**` segments, (3) more literal characters, (4) fewer wildcards; a full tie goes to the zone listed later in `territory.toml` (later path within a zone). So `payments/api/**` beats `payments/**` beats `**/*.md`; `src/*.rs` beats `src/**/*.rs` beats `src/**`. Leading-literal-first means a deeply nested directory glob beats a broad extension glob (`payments/docs/**` beats `**/*.md`), which matches how CODEOWNERS-style files are read. The sorted order is computed at compile time, so a lookup is a linear scan that stops at the first match.

**Guards: present fields replace, absent fields keep.** `sealed` is the exception: `DEFAULT_SEALED` always applies and `guards.toml` entries are appended (also when the list is empty or repeats a default; `CompiledPolicy::compile` re-adds the defaults, so a policy built by hand cannot drop them either). `protected_branches` and `destructive.ban` replace their defaults when the key is present, even as `[]` (the way to switch a default off), and keep them when the key is absent. Presence is detected on the parsed TOML document, because the frozen `Guards` type cannot tell absent from empty. Numeric limits default as in `Destructive::default()`.

**Ban patterns are full-match.** `*` matches any run of characters (including `/` and spaces), everything else is literal (including `?` and `[`), and the whole command, words joined by single spaces, must match. So `git reset --hard` bans only that exact command and users write `git reset --hard*` to cover arguments. The default list was therefore changed from the plan's `git reset --hard` to `git reset --hard*`: `["git push --force*", "git reset --hard*", "git clean -f*"]`. Pattern whitespace is trimmed and collapsed to single spaces. Ban patterns are always case-sensitive, also on case-insensitive filesystems: flags differ by case (`git branch -D` vs `-d`), so folding would ban safe commands. Normalizing the program word (`GIT.EXE` to `git`) belongs to shell analysis. An empty pattern, or one made only of `*`, is a policy error.

**Path and branch case.** Sealed, zone and protected-branch globs follow the caller's `case_insensitive` flag. Branches use it too, because on a case-insensitive filesystem `Release/x` and `release/x` are the same ref file.

**Teams.** `owner_pilots` is the lowercased, sorted, de-duplicated emails of the owners, with teams expanded. Errors: a `team:` owner naming no team; team names that could not be referenced (outside `[A-Za-z0-9_.-]`); two team names differing only in case; members that are not email addresses. A duplicate exact key is already rejected by TOML (reported as a syntax error with the line). A team with no members is a warning (an `owned` zone owned only by it is unwritable). Other semantic errors: invalid globs, zones with empty `paths`, `owned` zones without owners, an empty `default_target_branch`.

**Errors.** Every problem found is reported at once (`PolicyError::Invalid { problems }`, ordered config, guards, territory, then position), each with file, line and column (1-based, in characters; a BOM is skipped), a `ProblemKind`, a message and a fix. Positions come from the `toml` crate's spans: schema errors use the error's own span, semantic errors are located by walking the parsed document (`DeTable`), falling back to the enclosing element. Semantic checks run only when all three files parse, because they need the typed values. `CompiledPolicy::compile` on already-typed values returns the same problems without positions.

**Hash.** `policy_hash` is `ContentHash` (SHA-256) over a framed byte string: a domain tag, then for each of config, guards, territory its name and either an absent marker or a length and the bytes. An absent file therefore differs from an empty one, and content cannot move between files unnoticed. Policy directory contents beyond these three files (lore) are not part of the hash.

**Cache.** One file, `policy.json`, in the directory the caller passes (`RepoHome::cache_dir()`; this crate does not depend on `acs-store`). It stores the effective validated source (`PolicyFiles`: config, guards with defaults merged, territory) plus the hash, a format number and the crate version. Globs are not stored: compiling them costs microseconds, and one entry then serves both case-sensitivity settings. The entry is always the *last valid* policy: it is replaced only by a successful load, and an invalid or unreadable policy falls back to it. A format or version mismatch is a silent miss (bump `CACHE_FORMAT` when built-in defaults change); a corrupt file is ignored with a warning; an entry whose contents no longer compile is treated as corrupt. Writes go to a temporary sibling (`0600` on Unix) renamed over the cache file; a failed write is a warning. Warnings are returned, never printed.

**Performance.** A cache hit reads the three files, hashes them, reads and parses `policy.json`, and compiles about 60 globs. Measured in a release build with 20 sealed globs, 30 zones (two globs each) and 5 teams: mean about 0.2 ms (best 0.18 ms) per `load_cached`. The test in `tests/policy.rs` enforces 1 ms in release builds and a loose 25 ms in debug builds.

## Consequences

- The engine and later crates (lore scopes, `acs-paths`) can use `acs_policy::glob::Glob` for the same dialect.
- `CompiledPolicy::builtin` panics (`unreachable!`) if the built-in constants ever fail to compile; a unit test compiles it for both case settings, so this cannot ship.
- The default ban list does not catch `git push origin main --force` (flag after the arguments); that form is covered by the shell analysis's `force_push` flag and the protected-branch rule in the engine. Add `git push * --force*` to a repository's `guards.toml` to ban it everywhere.
- Hooks must treat `LoadOutcome::warnings` as user-visible context, since an invalid policy file otherwise degrades enforcement silently.
